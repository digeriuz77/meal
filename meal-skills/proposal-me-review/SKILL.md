# Proposal M&E Review and RFP Compliance Check

## Purpose and Trigger
Conduct an independent technical review of the M&E section of an Education proposal, concept note, or annex across 9 scored dimensions, AND optionally run a requirement-by-requirement RFP / funder guideline compliance check cross-referenced against the proposal logframe and budget. Technical review supports competitiveness and coherence; donor procurement rules must always be verified directly against the RFP.

Apply [Epistemic Contract](../../meal-references/epistemic-contract.md), [Education MEAL Standards](../../meal-references/education-meal-standards.md), and [Funder Formats](../../meal-references/funder-formats.md).

## Input Classification and Intake
Support two complementary modes (or run combined when an RFP/NOFO/funder guideline is supplied):
- **Mode A (Proposal M&E Section Quality Review)**: Classify document type before scoring: Full Proposal M&E Section (all 9 components expected), Concept Note (assess components 1 to 3; note others intentionally deferred rather than scoring `FAIL`), Expression of Interest (minimal review), Standalone M&E Annex (full review), Narrative description (`"not confirmed present"` for silent items), Logframe only (assess components 2 and 3 partially), or Partial Draft.
- **Mode B (RFP & Cross-Document Compliance Check)**: Extract every Administrative/Format, Technical, M&E-specific, Budget, and Scoring Criterion requirement from the RFP (distinguishing mandatory `must/shall` from preferred `should`, including requirements embedded in narrative paragraphs), map proposal coverage (`Addressed / Partial / Missing`), and cross-check proposal claims against Logframe/M&E Plan/Budget files.
- **Non-MEAL input**: Return suitability note and stop.

State intake mode (`project-context/`, designated folder, or explicit files), document type, named funder format (if any), and Evidence IDs (`filename#heading`, page, table, row).

## Scoring Thresholds (Mode A)
- **PASS**: Complete, coherent, proportionate, and competitive.
- **PARTIAL**: Present with significant gaps or missing specifics.
- **FAIL**: Missing, contradictory, or fundamentally non-competitive.

**Overall Rating:**
- **Strong**: `0 FAIL`, max `1 PARTIAL`.
- **Adequate**: `0 FAIL`, `2+ PARTIAL`.
- **Needs Revision**: `1 FAIL`, or `3+ PARTIAL`.
- **Major Issues**: `2+ FAIL`.

## Nine Proposal M&E Review Dimensions (Mode A)
1. **M&E Approach**: Specific to the Education program (zero copy-paste boilerplate), named methodology (RBM, utilization-focused, CLA), appropriate mixed-methods rationale.
2. **Results Framework / Logframe Alignment**: Embedded or existing annex; clear Goal -> Outcome -> Output hierarchy matching proposal narrative (no unmeasured narrative promises or contradictory targets/populations/geography).
3. **Key Indicators**: Outcome/learning indicators included alongside outputs, with baselines/targets and Education standard indicators (SDG 4, UNESCO UIS, INEE, EGRA/EGMA, funder standards) where relevant; proportionate indicator count; refer once to `indicator-quality-review` for deep SMART scoring.
4. **Data Collection Methods**: Methods tied explicitly to indicators/levels (EMIS, LMS, learning assessments, classroom observations, surveys/KIIs), sampling rationale, school-calendar alignment, and child safeguarding/assent sensitivity.
5. **Evaluation Plan**: Planned baseline, midline, and/or endline/final evaluations aligned to implementation timeline, scope, independence provisions, and dedicated evaluation funding.
6. **Data Quality Assurance**: Specific VIPRT/DQA procedures, verification methods, observation IRR, EMIS checks, and data management/minor PII protection (beyond `"data quality will be ensured"`).
7. **Learning and Adaptation (CLA)**: Specific reflection meetings, learning questions, school/community feedback loops, frequency, and decision triggers linking findings to adaptive management.
8. **M&E Budget**: Visible integrated or standalone M&E budget proportionate to scope (note typical 5% to 10% industry context cautiously without fabricating RFP rules), covering staffing, assessments, evaluations, translation, tools/tech, travel, and safeguarding.
9. **M&E Staffing**: Dedicated M&E roles proportionate to scale, explicit LOE, and partner/school data capacity addressed.

## RFP Compliance & Competitive Positioning Checks (Mode B)
When an RFP / NOFO / donor guideline is supplied:
1. Number every requirement (`A*` Admin/Format, `T*` Technical, `M*` M&E-specific, `B*` Budget) and score `Addressed / Partial / Missing`. (`"We will monitor and evaluate"` does NOT satisfy `"detailed M&E plan with SMART indicators"`.)
2. Audit **Page Limits & Mandatory Formatting** (exceeding page limits or violating format rules is a **Critical Issue** risking disqualification).
3. Audit **M&E Deep-Dive**: required standard indicators, mandated evaluation designs, baseline/endline requirements, equity disaggregation, reporting cadence, and genuine CLA vs. boilerplate.
4. Analyze **Competitive Positioning** against RFP evaluation weights (highlighting M&E scoring weight if stated).

## Output Format
Frame issues clearly in competitive and compliance terms:
1. **Proposal M&E Review Summary**: Intake Mode, Document Type, Funder Format, Overall Rating, and 9-row Score Summary table (plus Compliance Summary Table & `% Addressed/Partial/Missing` if Mode B ran).
2. **Exact Standalone Severity Headings**:
   - `## Critical Issues`
   - `## Important Issues`
   - `## Minor Improvements`
   (Write `"None identified from supplied files."` or `"Not assessable from supplied files."` if empty.)
3. **Priority Recommendations** (3 to 5 high-impact competitive fixes).
4. **Detailed Findings** (Sections 1 to 9, plus Requirement Coverage Tables & Competitive Positioning if Mode B ran) and **Design Flaw Flags**.
5. **Unresolved Decisions (`DES-D*` / `MEAS-D*`)**.

## Output Rules and Resumption
- Distinguish mandatory RFP requirements (`must/shall`) from general best practice (`should`).
- Keep supplied facts, assumptions, and proposed text revisions separate. On resume, verify revised proposal sections against original RFP and framework files.
